# 1. Introduction

The Enterprise Hospital Management System (EHMS) will be developed using an Agile-based iterative approach. The project will be divided into well-defined phases, allowing continuous planning, design, implementation, testing, and documentation.

This methodology supports incremental development while ensuring high software quality and maintainability.

---

# 2. Development Model

The project follows an Agile Scrum-inspired methodology.

Key principles include:

- Incremental development
- Continuous documentation
- Modular implementation
- Frequent testing
- Continuous improvement
- Version control using Git

---

# 3. Project Phases

The project is divided into the following phases:

1. Project Initiation
2. Hospital Business Blueprint
3. Software Requirement Specification (SRS)
4. System Architecture
5. Database Design
6. UI/UX Design
7. Backend Development
8. Frontend Development
9. Testing & Quality Assurance
10. Deployment
11. Future Enhancements

Each phase must be completed and reviewed before proceeding to the next.

# 5. Coding Workflow

The development process for every feature will be:

- Understand the requirement.
- Design the solution.
- Implement backend APIs.
- Implement frontend screens.
- Test the functionality.
- Update documentation.
- Commit changes to Git.

No feature will be considered complete until documentation and testing are finished.

---

# 6. Testing Strategy

Testing will include:

- Unit Testing
- Integration Testing
- API Testing
- End-to-End Testing
- Performance Testing
- Security Testing
- User Acceptance Testing (UAT)

Testing will be performed throughout development rather than only at the end.

---

# 7. Documentation Strategy

Documentation will be created before implementation whenever possible.

The project documentation includes:

- Project Initiation
- Hospital Business Blueprint
- SRS
- Architecture
- Database Design
- API Documentation
- UI/UX Documentation
- Deployment Guide
- User Manual

---

# 8. Quality Assurance

The project will follow these quality practices:

- Code reviews
- Consistent coding standards
- Version control
- Automated testing (future scope)
- Documentation review
- Security review

---

# 9. Deliverables

Each phase should produce:

- Approved documentation
- Source code (if applicable)
- Updated Git history
- Test results
- Review checklist
